## Where Mario's line falls: a prefill is a placeholder, never a stored value

Read against the four things the brief names:
- **The 30-minute prefill** (`_restDraft.mins=30` at open, :1387; m3: 14/14 opens, stored "as if typed" on a1 and the walk case). A prefill. It goes. The time wheel opens on the zero face `0:00:00`, which stores nothing (D215).
- **The RPE 5 chip default** (`_restDraft.rpe=5` at open; m3 a1/b/c/walk all stored `rpe:5` he never tapped). A prefill. It goes. No chip is selected at open on an empty record, and a Log with no chip stores no `rpe` (D219's rule, carried to the sheet). The hero and journal already print `RPE —` for a missing RPE.
- **Any wheel's opening face.** On an empty record every wheel opens on its zero face: a placeholder that stores nothing. On a record, the wheel opens ON the record (`0:30:00`, `3.10`, the RPE 5 chip dark): that is the record, not a prefill, exactly as Mario said. Nothing is re-saved by showing it.
- **Log tapped with nothing rolled.** On an empty record: nothing is written, not `{restLog:{}}`, not `{week,ts}` (m5 C1: either shape freezes the day and flips Progress to its second empty card). The sheet stays open and says so. On a record with the face unchanged: nothing is written; the button already reads `Logged ✓` and a tap on it is ‹ Back.

The line: **a number the athlete rolled, typed or tapped is a record; a number the sheet put there is not, and the only numbers the sheet ever puts there are the athlete's own stored ones.**

## D228 P-RESTWHEEL — the sheet shows the record and the face is the record; Log replaces; Clear removes; no defaults

**Finding.** m3: the sheet never reads the store (14/14 per version; re-entry shows `minutes="30" miles=""` over a stored 3.1); 30 min and RPE 5 are stored on every log the athlete did not set them on (a1, walk); no edit or clear path exists (0 sites delete a `restLog` type or an `ia_logs_` day key; the only remover is `purgeProgData`); a re-log doubles (d: `{mins:60, dist:6.2}`). m4: Mario's W2 WED reads `60 min run logged · RPE 7` after one Log of 1 mile, explained only by a second call in the 360 ms window (route table: two calls at the 30 prefill give `{mins:60, dist:2, rpe:7}`), and he cannot correct it. m5 B4: the D226 sum passes the box's own `max="600"` (400 + 400 stores 800; one typed 900 stores 900; 0 readers compare to 600).

**Coaching ground.** The log is the athlete's record of what the watch showed (D213). A record the athlete cannot see again is not a record to him, and a record he cannot correct is a lie he has to live with. On the card the regime is "the record, not the thumb, owns the number" (D218): a stored value opens as `Logged ✓`, a roll makes it `Log`, and Log commits the face. The sheet speaks the same grammar. D226's "Log more never overwrites" was built against a sheet that opened blank with a 30 prefill, where a second log blindly replaced the first (V237: 37 → 20). With the sheet opening ON the record, nothing can be replaced blindly: the athlete rolls the stored number to the new one while looking at it. So the sum retires for the same type (D226 amended below); a second type still gets its own key.

**What changes.**
1. **Open reads the store.** `openRestSheet` reads the day's entry through `getLogs()` (the lens). The selected type is the first `restLog` type holding a record, else `cardioTypes[0]` (walk is still appended last). The time wheel's hidden value is the record's `mins` (or `''`), the distance control's value is the record's `dist` (or `''`), and the chip matching the record's `rpe` is selected. A chip of any type holding a record prints a check: `Run ✓`. Every re-render of the cardio view (a chip tap) re-seeds from the selected type's record, never from a draft the athlete did not log (the same posture as P-DRAFTCHIP on the card: an unlogged roll is not a record, and that item stays queued).
2. **No defaults.** `_restDraft` opens with `mins:''`, `dist:''`, `rpe:null`. No chip selected. The 30 and the 5 are gone.
3. **The button is a regime, as on the card.** With a record for the selected type and every control equal to it (numbers compared as numbers), the button reads `Logged ✓` and a tap closes the sheet, writes nothing, shows no toast. Once any wheel, box or chip differs from the record, or there is no record, it reads `Log it`.
4. **Log replaces.** `applyRestCardio` flushes the wheels first (as Done does, D179), then writes `restLog[type]` = the face: `mins` when the time is above zero, `dist` when the distance is above zero (never on walk), `rpe` when a chip is selected. A chip tapped off (tapping the selected chip deselects it) removes `rpe`. A stored RPE that matches no chip is kept unless a chip is tapped (cannot happen today: every writer, V237's and V238's, wrote 5, 7 or 9). `week` and `ts` are stamped as today. The seven session keys are never touched (D223). Toast: `30 min run logged ✓` (rounded whole minutes), or `3.1 mi run logged ✓` when there is no time.
5. **Log with nothing to log.** Empty record, time and distance both zero: no write, sheet stays open, toast `Nothing to log yet. Add a time or a distance.` (walk, which has no distance control: `Nothing to log yet. Add a time.`). Record present and the face rolled to all zero: no write, sheet stays open, toast `To remove it, use Clear.` One path to deletion, and it is the explicit one.
6. **Clear.** Below `Logged ✓` / `Log it`, when the selected type holds a record, a button `Clear this run` (`ride`, `swim`, `row`, `walk`: the hero's sport words). First tap arms it: it reads `Tap again to clear` and nothing is written. Second tap removes `restLog[type]`; if `restLog` is then empty the `restLog` key goes; if the entry then holds no key but `week` and `ts`, the day key is deleted from `ia_logs_` (m5 C1: an emptied record would still freeze the day and flip Progress to `Log sessions to see…`). If the entry holds anything else (a moved-in session's fields, even as `''`, or `sets`, `parked`, `notes`), the key stays and those bytes are untouched. Then the sheet closes, the week view re-renders, toast `Run cleared` (sport word). The armed state resets on every open, so a ‹ Back after one tap disarms it.
7. **Ceiling.** `max="600"` leaves with the box. The time wheel's own face (`0..9` hours, 9:59:59 = 599.98 min, D199/D208) is the per-record ceiling, and it is enforced by construction. No sum exists after this ruling, so the "does the sum respect 600" question (§12) dissolves. A legacy record above the ceiling (800 from a V238 sum) opens with its face pegged at 9:59:59 for display (D208) while its hidden value stays `800`, so the button reads `Logged ✓` and nothing is rewritten unless the athlete scrolls.
8. **Rest hero button.** `Log more` becomes `Edit cardio` whenever the hero prints a jog line; `Log cardio` otherwise.

**D226 amended (same-type arm superseded).** "Log more adds same-type minutes and distance and keeps the higher RPE" is replaced by: "Log writes the face over the type's record; the athlete sees the record on the wheels before he changes it." The cross-type sentence stands: "a second type gets its own key" and the first type is kept whole. The g238 row `D226-logmore` is restated below.

**What deliberately does NOT change.** The `restLog[type]` shape (`{mins, dist?, rpe}`, numbers; walk never carries `dist`, A6). `persistLogFields`' carry. `restNorm`. `restMoveCandidates`. The MILES, Progress, `seedFromPriorPrograms` and `ladderWeekly` arithmetic. The seven session keys. The menu view's two rows and their copy. The chips' three words and numbers (5 Easy, 7 Steady, 9+ Hard) and the `Noted` note at 9+ (P-RPEWORDS, below). The strip cell (`WED — 7 REST`, no jog mark: the strip is the calendar; the record is behind the tap). The today hero on a double day (the detail sheet carries the jog, D231). `buildProgram`.

## D229 — distance alone is a record; each type has its own controls and units; the sentence carries the distance

**Finding.** m3 a2: minutes cleared and 3.1 typed refuses with `How long did you go?` and the 3.1 is lost on close (2/2 per version). m5 B1: the distance box is one node reused five ways: `Distance (miles)` for run, bike and row, `Distance (yards)` with `step 0.1` for swim, none for walk; `restLog.bike.dist` and `restLog.row.dist` are stored and read by nothing. m5 C2: a mins-less record (T1 `{dist:3.1, rpe:7}`) is counted by MILES, Progress, seed and ladder and hidden by the journal (row with no line) and the hero (no line, `Log cardio`). m5 B3: a sheet wheel cannot reuse `log_run_mins`/`log_run_dist` (the closed detail sheet keeps its markup and wins `getElementById`); `iaWheelHTML` takes any hidden id; nothing listens unless `iaWheelInit` runs on the sheet.

**Coaching ground.** A rest-day jog has no prescription, so neither dimension is fixed: the athlete logs what he knows, time, distance or both, and the app invents the third from neither. A distance with no time is a run; MILES already credits it, and two readers hiding what four count is the kind of split that made Mario's miles "look lost" (m4: no surface shows Wednesday's miles on their own). Wheels: the D1 test (V182, as amended V232/V233) is natural bounds and a separator the keyboard fights. Time (h:mm:ss) and miles (nn.n) pass it; yards and meters are plain integers and keep a box, as swim yards do on the card. Units follow the sport: miles for run, bike and row distance on the roads is not how a rower reads an erg, so row takes meters; swim takes yards as the card does (`step="25"`, :13926).

**What changes.**
1. **Minutes are not required.** `applyRestCardio` writes a record when time or distance is above zero. `{run:{dist:3.1}}` is a legal write (it was already a legal read through the lens, A2).
2. **Controls by type, with the sheet's own hidden ids `rest_mins` and `rest_dist`** (never `log_run_*`), initialised with `iaWheelInit(restBody)` after every render of the cardio view and flushed on Log:
   - run: `TIME` = `iaWheelHTML('hms','rest_mins',…)` (caption `Time`); `DISTANCE` = `iaWheelHTML('dist','rest_dist',…)` (caption `Miles`).
   - bike: the same two wheels (the card's bike form is time only because the engine prescribes a ride by time, D207; a rest ride has no prescription and the record keeps what the watch showed; from this build the sheet itself reads `bike.dist` back, so it has a reader).
   - row: the time wheel and a box, label `DISTANCE (METERS)`, `<input class="rd-input" type="number" inputmode="numeric" min="0" id="rest_dist" placeholder="meters">`, no `step` attribute (the browser's own default of 1 is not a constant of ours).
   - swim: the time wheel and the card's own yards box, label `DISTANCE (YARDS)`, `inputmode="numeric" min="0" step="25" placeholder="yards"` (the `step 0.1` defect ends with the shared node).
   - walk: the time wheel only (A6, unchanged).
   The word `optional` leaves both labels: either is enough and the refuse toast says so. No `max` attribute anywhere in the sheet.
3. **Units stored as the control's**: miles (run, bike), meters (row), yards (swim), numbers (`parseFloat` of the hidden or box value; the dist wheel's `5.20` stores 5.2; the time wheel's decimal minutes store as they come, seconds kept).
4. **The sentence (`restLogLines`), hero and journal alike, prints every record that holds time or distance** and names what it holds. Time leads when present; the distance follows `logged`; RPE closes it; a record with distance alone leads with the distance. Whole minutes for display (`Math.round`); the stored seconds stay. Unit words `mi`, `yd`, `m`:
   - `{mins:30, dist:3.1, rpe:5}` → `30 min run logged · 3.1 mi · RPE 5`
   - `{mins:30, rpe:5}` → `30 min run logged · RPE 5` (byte-identical to V238)
   - `{dist:3.1, rpe:7}` → `3.1 mi run logged · RPE 7` (V238: no line)
   - `{mins:37.47}` → `37 min run logged · RPE —`
   - bike `{mins:45, dist:12, rpe:5}` → `45 min ride logged · 12 mi · RPE 5`
   - swim `{mins:20, dist:1500, rpe:5}` → `20 min swim logged · 1500 yd · RPE 5`
   - row `{mins:20, dist:5000}` → `20 min row logged · 5000 m · RPE —`
   - walk `{mins:30, rpe:7}` → `30 min walk logged · RPE 7` (byte-identical)
   A legacy lensed `run:{dist:3.7}` (A2's `run>swim` case) now prints `3.7 mi run logged · RPE —` under the swim line: the record coming back, the same ground A2 accepted the ride line on. Every V238 line without a distance is byte-identical.
5. **Toast** is the sentence's head plus `logged ✓`: `30 min run logged ✓`, `3.1 mi run logged ✓`, `20 min swim logged ✓`.

**What deliberately does NOT change.** `_IAW_SPEC` (no new wheel kind; the sheet reuses `hms` and `dist`). The card's forms and ids. Walk's no-distance (A6). MILES/Progress crediting rules (bike credits minutes, swim credits yards, walk and row credit no total). The journal's `RPE n — <RPE_LABELS>` header for a session RPE.

## D230 P-SHEETCLOSE — a sheet that is not open takes no touch; every sheet

**Finding.** m5 A1: 9 sheets (`.overlay` ×3, `.rand-overlay` ×6) stay hit-testable for 360 ms after `open` is removed (`visibility 0s linear .36s` at :886); 0 `pointer-events` rules on any overlay; none of the 11 close functions clears a body or resets a draft. m5 A2: of 12 closing writers, 7 change state on a second call: sum (`applyRestCardio`), duplicate (`applyOverlayDraft`, `applyInjuryDraft`: overlays 0 → 1 → 2), toggle (`handleDayStatus` Done, Skip, Mark Done: `Done ✓` then `Unmarked`), rewrite (`commitMileChange`: `mileBestSrc.from` loses `{10:30, entered}`); 5 idempotent, 4 of which repeat their toast. m5 A2b: 13 non-closing detail writers (`stepSet` ×30, `setDelta` ×15, `onSetWeight` ×15, `skipExercise`, `skipSuperset`…) sit under the finger while the detail sheet slides down after Done; unmeasured. m4: a second click in that window is the only code-side route to Mario's `60 min · 2 mi`.

**Coaching ground.** A closing sheet has said goodbye. A touch on it is the athlete's finger coming off the button, not a decision; the app may not treat it as one. The rule is on the sheet, not the button: a per-handler latch would need twelve latches, would leave the 13 non-closing writers of A2b uncovered, and would have to pick between a toggle's two meanings. What must be true: **from the moment a close function removes `open`, no element of that sheet receives a touch, through its slide-out and after; a sheet receives touches only while it carries `open`.** All 9 sheets, because the rule is one rule and the cost is proof time, which Mario already weighed against a second build on one surface and rejected.

**Coverage, by button, as the rule reaches it.** Rest `Log it` (also idempotent by D228 item 3: a second call with the face unchanged writes nothing), rest `Clear` second tap, rest `Move it here`; detail `Done`, `Skip`, `Mark Done ✓` and every non-closing set control under them; swap `applySwapChoice`; add `applyAddChoice`; wildcard `completeWildcard` (the queued second popup timer included); change `applyOverlayDraft`; injury `applyInjuryDraft`; goal `commitGoalChange`; mile `commitMileChange`; every `‹ Back`, `Got it`, `Keep what I have`, `Stay the course`. The `.pop-overlay` and `.rpe-overlay` sheets already close at 0 ms and are covered trivially.

**Exceptions, named.** `resetWildcardCounter`'s designed second tap (m5 Q2) is on an OPEN sheet and is untouched: it is a confirm, not a closing-window touch. The detail foot's `Done ✓ tap to undo` (m5 A3) is on an open sheet and is untouched. The new rest `Clear` two-tap is the same pattern. `prefers-reduced-motion` already has a 0 ms window and is unaffected.

**Form.** The session's (a `pointer-events` rule on the closed state of `.overlay` and `.rand-overlay`, restored on `.open`, is the obvious one and switches instantly because `pointer-events` is not in the transition list at :886; a latch is acceptable if it covers A2b too). The gate rows below give an oracle for each form.

**What deliberately does NOT change.** The 360 ms slide-out itself. `handleDayStatus`' toggle on an open sheet. Every close function. No body is cleared and no draft reset at close (D228 resets the rest draft at OPEN).

## D231 — which days open the sheet: a future rest day says why; a moved-from day takes a jog and never a move; a double day edits its jog from the session card

**Finding.** m3: a future rest day is inert and silent (`openDayKey` :11869 returns before `openRestSheet`'s toast). m5 B6: 12/12 against the hand calendar: past and today open, future this week and future weeks silent; before start toasts `Before your start date`. m5 B6: `That rest day has not come around yet` (:1384, 1 site) is reachable on exactly one path, and the day it names has already come: move today's THU session onto WED, THU becomes `{rest:true, moved:true}`, the hero switches to rest mode and renders `Training anyway?` and `Log cardio`, and both toast, because `restDayEligible` refuses `day.moved`. m3 and the V238 ruling: once "Training anyway?" moves a session onto a logged jog, `openDayKey` routes to `openDetail` and the jog can be seen only in the journal and MILES; it cannot be edited.

**Coaching ground.** Silence is the one answer a coach never gives. A day whose session moved away is a rest day now; a jog on it is a rest-day jog like any other, and refusing it with a sentence about the calendar is wrong twice. It is not a move destination (a chain of moves is rescheduling, which `applyRestDayMoves` was not built for; the comment at :1559 says so), so the honest sheet simply does not offer the move. A double day is one day with two efforts (D223); the session card is where the athlete handles that day, so that is where the jog is shown and edited.

**What changes.**
1. **Eligibility splits in two.** Jog-eligible(w,d): not before start, the date has come, and the day is a rest day or its entry holds `restLog`. Move-eligible(w,d): jog-eligible, `day.rest`, not `day.moved` (today's `restDayEligible`, unchanged in meaning). `openRestSheet` refuses only when not jog-eligible, with the existing toast; when jog-eligible but not move-eligible it opens straight on the cardio view and renders no menu.
2. **Future rest day.** `openDayKey` on a rest day calls `openRestSheet` and lets it answer: toast `That rest day has not come around yet` (existing string, :1384), no sheet.
3. **Moved-from day.** The rest hero on a `day.moved` day renders only its cardio button (`Log cardio` / `Edit cardio`), never `Training anyway?`. A strip tap opens the cardio view. `restMoveCandidates` still skips `moved` and `movedFrom` days as origins (unchanged).
4. **Double day.** The detail sheet of a day whose entry holds a `restLog` prints a block above the session's first section: label `ALSO ON WEDNESDAY` (the day's name), one sentence per type from `restLogLines`, and a button `Edit cardio` that calls `openRestSheet(w, dayKey, 'cardio')`. The rest sheet opens over the detail sheet (restOverlay sits after detailOverlay in the document). After its Log or Clear the detail sheet re-renders so the block is current (`openDetail` is its own re-render path, :14225). A Clear on a double day leaves the session's keys byte-identical (D228 item 6).

**What deliberately does NOT change.** `Before your start date` and its order. `applyRestMove`, `applyRestDayMoves`. The strip tap on a training day. The today hero on a double day (no jog line there; the card has it). `restMoveCandidates`.
