**PRIORITY 1 (Mario, Post-V239): semantic versioning.** Every version this skill reads, prints or writes is `MAJOR.MINOR.PATCH` with a lowercase v (`v0.240.0`), never a future `V<N>` or a bare integer. `V1` to `V239` are history and keep their names (V239 = 0.239.0). A future `V<N>` found anywhere is a defect: use the dotted form and report the correction. CLAUDE.md, PRIORITY 1, has the names.

The handoff is ONE document with a stable filename, overwritten in place. Never append a session narrative to the top; never create a second changelog. Work the seven elements in order and confirm each landed (grep it back).

0. **Did this session ship a version?** If `ia-version` did not move, it did not. Do NOT bump anything and do NOT invent a version: keep the working-file line where it is, add the session as its own bullet above the previous `Prior work` bullet, and give it a digest line named for what it was (`- **Post-v<version> … session — no build.**`; `Post-V<N>` before semver). Elements 2–5 and 7 apply unchanged. Precedent: `Post-V154 rulings session — no build.`
1. **Current state header** — set the working file / `ia-version` line to v<version>; rewrite the "Most recent work (v<version>)" bullet in the established voice: what was reported, what the measure pass found, what shipped (by D-code), what the proof showed (the feature tests that hold it, pass/total, and how many failed on the previous release; the CI run id and its jobs; hunks classified), what was flagged. Update the live-program line if Mario's config moved.
2. **Numbered sections** — fold durable behaviour next to the code it describes (§4 persistence, §5 engine, §5b/§6b overlays, §6 fatigue, §7 DS, §8 logging/progress, §8b swap, §9 workflow). Delete or rewrite sentences the build made false.
3. **§10b** — promote any lesson that outlives this version. Generic engineering doctrine only, one bullet, tagged with the version in parentheses.
4. **Rulings** — every ruling Mario made this session is an entry in its feature's `docs/decisions/<feature>.md` (Mario, Post-v0.239.1) WITH the reasoning that produced it and any recommendation he rejected; fill in the release line of each one this version shipped. §11f gets one line per ruling: its D-code, a one-sentence summary and its decision file. Rulings recorded in §11f before Post-v0.239.1 stay there.
5. **§12** — add what is carried forward; DELETE what this build closed (do not annotate as closed).
6. **Digest** — add ONE line to the `## Recent sessions (digest)` block: `- **v<version>** — Patch|Minor|Major: …` (the bump class Mario picked comes first; pre-semver lines stay `- **V<N>** — …`). **The block runs newest FIRST**, so the new line goes directly ABOVE the previous version's line, not at the end of the file. (Older entries further down are out of order — V182/V183 sit above V189 — so read the immediate neighbours, not the whole block, to place it.) A session that shipped no version still gets a line, named for what it was rather than a version: `- **Post-v<version> … session — no build.**`
7. **Session-start check** — `grep -oE 'name="ia-version" content="[^"]+"' index.html` must match the version you just folded, and there must be exactly ONE digest line for it. Count the digest line specifically, not the prefix: `grep -c '^- \*\*v<version>\*\* —'` (with the em-dash). A bare `grep -c '^- \*\*V<N>'` also catches §12 items such as `- **V190 watch items.**`, so it reads 3 or 4 on a healthy file — that is not a duplicate. If any earlier version has no digest line, say so in the entry and reconstruct it from the header, marked "(reconstructed)".
